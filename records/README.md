# records/ — первичные записи

Каталог первичных записей проекта.
Формат основан на Envoy `Minimum field record`.

## Назначение

`records/` хранит первичные данные, полученные в ходе работы: наблюдения, действия, результаты, полевые логи, эксперименты. Это уровень ниже интерпретации и выводов.

## Правила

- Первичные записи не перезаписываются (I3). Исправления — через новую запись с указанием причины.
- Значимые утверждения уровня SUPPORTED / VERIFIED и типа RESULT должны иметь запись в `PROVENANCE.md` (I4).
- Переходы статуса знания фиксируются в `meta/transitions.md` (I2).
- Запись не удаляется. Устаревшее перемещается в `ARCHIVE/` с датой и причиной (I6).

## Формат записи

Обязательные поля:

    FIELD:          <область / контекст, где ведётся работа>
    OBSERVATION:    <что непосредственно зафиксировано>
    SOURCE:         <источник или процедура получения>
    ACTION:         <что было сделано>
    RESULT:         <что получилось>
    INTERPRETATION: <объяснение значения результата>
    HYPOTHESIS:     <проверяемое объяснение, если есть>
    UNKNOWN:        <что осталось неизвестным>
    NEXT STEP:      <следующее конкретное действие>

Расширения (когда применимо):

    TIMESTAMP:      <дата и время получения>
    PROVENANCE:     <ссылка на P-запись в PROVENANCE.md>
    ACTOR:          <кто/что выполнял>
    CONTEXT:        <условия, ограничения>
    CONFIDENCE:     <уровень уверенности с обоснованием>

## Именование

Формат: `NNN-<краткое-имя>.md`
- `NNN` — порядковый номер, три цифры с ведущими нулями (`001`, `002`, ...).
- Номер сквозной в рамках проекта, не сбрасывается.
- Пример: `001-field-kleros-baseline.md`.

## Дополнительные файлы

Запись может сопровождаться вспомогательными файлами в том же каталоге:
- `RAW-*.md` — сырые внешние выходы в исходном виде;
- `SYNTHESIS.md` — синтез по итогам записи;
- `RUN.md` — чек-лист прогона.

См. `docs/METHOD.md` (Run Structure, Git Rule).

## Иерархия уровней

Не путать с `docs/KNOWLEDGE_STATES.md`:

- `records/` — уровень первичных данных (сырое, захваченное);
- `PROVENANCE.md` — уровень привязки утверждений к источникам;
- `meta/transitions.md` — уровень фиксации смены статуса знания;
- `DECISIONS.md` — уровень решений;
- `CURRENT_STATE.md` — уровень текущего состояния проекта.

Данные из `records/` не подменяют ни один из этих уровней.
