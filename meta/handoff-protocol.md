# meta/handoff-protocol.md
Протокол передачи контекста между сессиями и агентами.
Применяется вместе с `meta/handoff-current.md` (текущий снимок) и `meta/agent-rules.md`.

## 1. Назначение

Протокол определяет, как передаётся контекст от одного агента (или сессии) к другому так, чтобы новый агент мог продолжить работу без реконструкции по памяти и без потери основания.

Handoff — транспортный формат и набор обязательных проверок, не замена первоисточникам.

## 2. Иерархия источников истины

Любое утверждение о внешнем артефакте требует источника. Приоритет — от высшего к низшему:

1. Текущий ввод оператора.
2. Свежий терминальный вывод (git status, git log, содержимое файлов) в текущей сессии.
3. Содержимое репозитория по конкретному SHA.
4. Документация проекта (INVARIANTS, CURRENT_STATE, DECISIONS, meta).
5. Handoff / сводки предыдущих чатов.
6. Память ведущего / реконструкция.

Уровень 6 не используется для утверждений о фактах. При конфликте берётся более высокий уровень.

Формат факта:

    [ФАКТ] HEAD = <sha>
    [ИСТОЧНИК] вывод оператора, <дата>

## 3. Свежесть

«Свежий» — полученный в текущей сессии, а не просто вспомненный или скопированный из предыдущего handoff.

Утверждение из предыдущего handoff не устанавливает текущее состояние. Новый агент обязан запросить актуальные данные, если текущее значение значимо.

## 4. Конфликт источников

При конфликте двух источников агент не сглаживает их молча. Обязан:

1. зафиксировать конфликт;
2. назвать источники;
3. предпочесть свежий авторитетный;
4. оставшуюся нерешённой часть помечать `[НЕИЗВЕСТНО]` до разрешения.

## 5. Маркировка утверждений

Каждое утверждение о прошлом, состоянии репозитория или содержании чужих текстов — с явной пометкой:

- `[ФАКТ]` — подтверждено источником, источник назван (соответствует VERIFIED).
- `[ПОДТВЕРЖДЕНО]` — SUPPORTED, проверка неполная.
- `[ГИПОТЕЗА]` — предположение, источник не подтверждает.
- `[НЕИЗВЕСТНО]` — данных нет.
- `[МОЯ ПОЗИЦИЯ]` — операционная или аналитическая позиция агента по текущему вопросу, не факт.
- `[ВНЕШНИЙ — <имя>]` — дословный вывод внешнего наблюдателя, присланный в текущем чате.

`[МОЯ ПОЗИЦИЯ]` никогда не используется для маскировки внешнего мнения. Дословный текст наблюдателя не восстанавливается по памяти.

## 6. Процедура старта нового ведущего

Новый агент не принимает handoff на веру. Обязательная последовательность:

**Шаг 1 — Верификация идентичности handoff.**
Сверить: проект, репозиторий, HEAD, активный эксперимент/задача. Что не сходится — зафиксировать как `[НЕИЗВЕСТНО]`.

**Шаг 2 — Верификация текущего состояния.**
Запросить свежие данные (git log, git status, содержимое ключевых файлов). Не полагаться на прошлые подтверждения.

**Шаг 3 — Зафиксировать пробелы.**
Что не удалось проверить — явно перечислить. Не заполнять предположениями.

**Шаг 4 — Установить полномочия.**
Проверить, что роль агента определена: что ему разрешено, что запрещено, кто утверждающий.

**Шаг 5 — Только после этого действовать.**
До завершения шагов 1–4 зависимые действия не выполняются.

## 7. Шаблон handoff (транспортный формат)

    HANDOFF PROTOCOL: <version>
    PROJECT: <project>
    REPOSITORY: <repository>
    CURRENT HEAD: <verified SHA / [НЕИЗВЕСТНО]>
    ACTIVE EXPERIMENT: <experiment / [НЕИЗВЕСТНО]>
    STATUS: <status>
    LAST OPERATOR DECISION: <decision / [НЕИЗВЕСТНО]>
    MANDATORY FILES: <list>
    UNVERIFIED: <list>
    OPEN QUESTIONS: <list>
    LAST RESPONSE NUMBER: <n>

Шаблон — транспортный формат, не замена проверке по первоисточникам.

## 8. Восстановление утраченного сырья

Если сырьё не было захвачено в момент события:

- допустимо повторно запросить у источника и сохранить как `archived-external`;
- архивная запись фиксирует: узел, чат, номер сообщения, дату повторной выдачи;
- если источник не сохранил дословный ответ — run фиксирует `UNKNOWN`;
- реконструкция из памяти или по резюме недопустима.

## 9. Anti-patterns (передача контекста)

- выдумывание отсутствующего состояния проекта;
- утверждение, что файл прочитан, когда он не читался;
- обращение со старым handoff как с текущим состоянием;
- выдача собственного анализа за вывод внешнего наблюдателя;
- молчаливое разрешение конфликта источников;
- старт зависимой операции при непроверенном состоянии;
- «делай как раньше» без явно определённой операции;
- реконструкция утраченного сырья по памяти.

До канонизации протокола нарушения трактуются как отказ протокола, а не как стилистический дефект.

## 10. Failure cases (сохранять)

Эти случаи — основание правил, не иллюстрации:

- утверждение «я менял корректно» без источника;
- ссылка на внешнего, которого не было;
- выдача собственного ответа за взгляд внешнего;
- правка, захватившая заголовки соседних слотов;
- указания «делай как раньше» без конкретики для нового ведущего;
- **зеркала разошлись.** Оператор заменил документы в одном хранилище, остальные не обновил. Handoff обязан назвать, какое зеркало актуально, и указать источник истины. Иначе принимающий агент может работать по устаревшей копии.
- **документ без адресата.** Агент принял проверочный материал, адресованный другому узлу, за свой и начал по нему работу. Правило: документ без пометки адресата — спросить, кому адресован, до начала разбора.

Новые failure cases добавляются в этот раздел и служат основанием для уточнения правил.
